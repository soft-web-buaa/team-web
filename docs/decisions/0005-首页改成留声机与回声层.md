# 决策记录 0005：首页改成留声机，回声怎么放

> 状态：已按组长授权实现 MVP，后面几项待定。整理：ClawsGO Science Agent，2026-11-24。
> 接 [0002](0002-刻声怎么用.md) 和 [0003](0003-版图与叙事.md)。

## 背景

组长 2026-11-24 的话：刻声放开，现在往全盛形态做；适配怎么有创意怎么来，可以分页，重构结构都可以；社区要扎扎实实；当下做的是 MVP，整个项目要推向极致；照片做唱片套子，定位是辅；冻结五色可以动，前提是做得好、不带 AI 味（见 `MEMORY.md`）。

0002 里的倾向是"先整体放进去保底，再试移植"。这次的做法比"移植并换数据"更窄：不改刻声的数据层，把社区层长在它上面。

## 做了什么

| 项 | 做法 |
|---|---|
| 首页 | `/` 整屏嵌入刻声分区图（iframe，`?embed=1`）。原首页挪到 `/now`，叫"此刻"。地图页 `/map` 保留，暂不进导航 |
| 回声 | 钉在一张声片某一秒的话。三处同时出现：播放器里的波形（针走到那一秒，话浮上来）、盘面刻纹上那一秒的位置（跟盘转）、可折叠的列表。示例回声 34 条，对准合成声里真正发生的那一秒，只写年级，每条标"示例" |
| 唱片套子 | 地点卡的正面是一张照片，右边露出半张盘。照片是辅。现在 16 张都是纸模型照，角标写"模型照"；实拍到位后换文件、改 `sleeves.json` |
| 主句 | 嵌入模式下卡片标题是「有些声音，比我们在这里待得久。」（0003 的倾向，组长未表态） |
| 字体 | 仿宋子集补 63 个字，只增不减 |

## 选项与取舍

| 选项 | 好处 | 代价 |
|---|---|---|
| A 外壳里重做留声机（Vue + three.js） | 一套代码、一套数据 | 3544 行的 `plan3d.js` 要拆，工作量大，容易把刻声做坏。刻声自己的蓝图写过：删掉搓盘就退化成录音加频谱图 |
| B 嵌入刻声，社区层长在它里面（本次） | 刻声的一切保留；两个文件加一段样式就接上；同源，落款和回声共用 `localStorage` | 外壳和舞台是两份代码、两份声音数据；iframe 内外的状态要靠 URL 和 `localStorage` 传 |
| C 只取母题，二维圆盘重画 | 手机稳 | 少了三维的惊艳，与"效果不能比刻声差"冲突 |

选 B 的理由：先让社区在最强的那个界面里成立，再决定要不要合并两份代码。

## 没验证的

- 回声带和盘面回声针只在无头 Chrome（软件渲染）里看过。手机真机的帧率没测。
- 两份声音数据没合并：刻声的概念盘有回声层，外壳 `SEED_SOUNDS` 的 8 段有它自己的另一套回声。用户会遇到两种"留一句话"。
- 回声只存在这台设备上，别人看不到。要变成真社区必须接后端（0001），后端接上时只改 `community.js`，函数注释里写了对应接口。
- 纸模型照的拍摄机位是同一个固定角度，没有逐个地点调。个别地点（如体育馆、游泳馆）取景是否合适，需要人看。
- iframe 里的读屏器体验没有测。

# 决策记录 0002：刻声怎么用

> 状态：组长已定方向，实现未开始。整理：ClawsGO Science Agent，2026-11-24。

## 背景

「刻声：北航的十秒声片柜」是组长的个人作品。组长上次个人项目的经验是：创意叙事和眼前一亮，是从同质化竞争里脱颖而出的因素（2026-11-23 的说法）。这次团队项目要在它的基础上做社区。

## 组长的话

- 2026-11-23：刻声主体可复用，但要做好适配；合成声音当 demo；史料音频可用，上传 GitHub 已批准。授权状态如实写在"关于"页：口头认可，书面授权待补，有异议就撤下。
- 2026-11-24：刻声放开，现在往全盛形态做；适配怎么有创意怎么来，未必是链接，可以分页；MVP 是雏形，整个项目要推向极致；这个留声机要成为标志之一，效果不能比刻声差。

## 我读到的

读了刻声的蓝图、文化简报、设计冻结、年轮和学期带的代码、`plan3d.js` 的渲染循环与启动段，约 700 行，没读完 3544 行。

1. **刻声自己的结论**（文化简报 §1）：刻声缺的不是功能，是"谁和谁之间发生了什么"。补法是给一张盘找第二个人。我们的社区层补的正是这一块。
2. **借声场和测房间在 `app.js`（主页），不在分区图页。** 分区图页只有刻盘、搓盘、听声寻片、年轮和学期带。所以刻声是两个入口，不是一个页面。
3. **年轮（`rings.js`）和学期带（`bands.js`）已经是跨年份叙事的现成版本**：同一地点按学期分圈，盘的外圈按学期分带，最早的在最外。
4. **渲染核心自洽**：`buildScene` 建场景，`frame` 每帧更新，读的数据只有声片列表和校园几何。声片到画面的接口很窄，换数据源可行。
5. **刻声最硬的资产是口径**：真假分层，只数 real，史料不冒充真人，"不许假陈述"。
6. **刻声明确不做的**：账号、SSO、社交动态（点赞、评论、关注），见蓝图 §1.11。我们的社区层恰好违反这一条，组长 2026-11-24 已放开。

## 三种做法

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A 整体搬入 | 刻声当独立页面，从首页链进去 | 最快，保底 | 两套视觉、两套数据，社区数据进不了盘 |
| B 移植并换数据 | 盘面读我们的声音和社区数据 | 视觉统一，成为标志 | 要改 `plan3d.js` 的数据装载，手机性能未测 |
| C 只取母题 | 用 2D 圆盘重画，不用 three.js | 稳，手机友好 | 少了 3D 的惊艳 |

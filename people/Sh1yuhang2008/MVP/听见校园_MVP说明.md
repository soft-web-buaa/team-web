## 1. 这份 MVP 是什么

一个可以现场演示的**主界面 + 核心交互**，用来验证课程项目的产品方向，而不是完整产品。

它把「校园声景地图」最关键的几件事跑通了：

- 一张能点、能筛选的校园地图；
- 一条 0–24 小时的时间轴，拖动时地图色调、天空、粒子、声音点一起变化；
- 一个 90 秒的「播放一天」，按时间自动触发声音；
- 一个声音详情抽屉：播放、波形、故事、声音记忆、收藏、票根；
- 一个「声音记忆」投稿流程，提交后进入「待审核」，只在本机可见。

**它不包含真实录音。** 所有播放声音都是 Web Audio 实时合成的提示音，用来验证交互与节奏；接入真实音频时，只需要把 `motif` 换成 `audio.src`。

## 3. 怎么运行

最简单的方式是双击项目根目录的 `start.cmd`，它会安装依赖、启动 `http://127.0.0.1:5173` 并打开浏览器。

命令行方式：

```bash
cd hear-campus
npm install
npm run dev        # http://127.0.0.1:5173
```

构建与本地预览：

```bash
npm run build
npm run preview    # http://127.0.0.1:4173
```

如果只想发给别人双击查看，构建独立版：

```bash
npm run build:standalone
```

然后打开 `dist-standalone/index.html`。它把 JS、CSS 和平面图都内联进一个 HTML，`file://` 下也能运行。

> 根目录的 `index.html` 是 Vite 入口，不能直接双击：浏览器在 `file://` 下会拦截 `/src/main.ts` 的 ES Module 请求，所以显示空白。这不是代码坏了，改用 `start.cmd` 或独立版即可。

> 路由使用 hash 模式：`/#/sound/snd-001`。静态托管不需要额外的 rewrite 配置，分享链接也不会 404。

## 5. 时间轴与主题

六个时段与主文档一致：

| slot | 时间 | 主题 | 粒子 |
|---|---|---|---|
| dawn | 05:30–07:00 | 冷蓝转暖 | 薄雾 |
| morning | 07:00–11:00 | 明亮清透 | 无 |
| noon | 11:00–14:00 | 高对比硬光 | 热浪 |
| afternoon | 14:00–17:00 | 暖、柔和 | 无 |
| dusk | 17:00–19:00 | 橙紫、长影 | 飞鸟 |
| night | 19:00–05:30 | 深蓝、灯光 | 萤火 |

实现要点：

- `themes/index.ts` 里存 6 套主题与 `slotAt()` 映射，处理了 19:00–05:30 的跨午夜区间；
- 主题通过 `data-slot` + CSS 变量下发，组件不写死颜色；
- 地图滤镜只作用于 `.campus-image`，不影响文字和控件；
- 拖动时只改主题与高亮，`@change`（松手）才播放当前时段代表声音。

## 6. 音频方案

没有音频文件，使用 Web Audio 合成：

- **环境底噪**：3 秒粉红噪声循环 + 低通滤波 + 持续 drone，按时间段改变 drone 频率；
- **声音动机**：每条声音一个 `Motif`（音高序列、波形、步长、衰减、噪声量），播放时调度振荡器与噪声爆发；
- **播放一天**：环境底噪持续，时段切换时播放该时段的代表声音；
- **浏览器策略**：第一次点击/按键时 `unlock()`，避免自动播放被拦截。

接入真实录音时：

1. 在 `Sound` 上加 `audio: { src, duration }`；
2. 详情页把 `engine.playMotif()` 换成 `<audio>` 或 Wavesurfer；
3. 播放一天仍可保留合成环境底噪，只替换代表声音。

## 7. 数据模型

MVP 使用简化版 `Sound`（`src/types.ts`）：

```ts
interface Sound {
  id: string
  title: string
  category: 'study' | 'life' | 'sport' | 'nature'
  slot: 'dawn' | 'morning' | 'noon' | 'afternoon' | 'dusk' | 'night'
  timeLabel: string
  place: string
  x: number              // 平面图像素坐标
  y: number              // 平面图像素坐标
  story: string
  duration: number
  credit: string
  motif: Motif          // 真实录音接入后替换为 audio
  memories: Memory[]
}
```

与主文档 Schema 的差异：

- 没有 `audio.src`，用 `motif` 代替；
- `time.axis/series_id` 尚未拆分，本期只有日轴；
- `credit.type/library/url` 未启用，因为没有档案素材；
- `status` 未启用，MVP 全量展示。

这些字段在主文档 v1.1 中已经预留，后续替换不需要重写页面。

- 底图是 `src/assets/campus-plan.jpg`，从北航学院路校区平面图裁剪主图区域（1361 × 1320），保留学院路、知春路、北四环、大运村路与建筑编号；

- 10 个点按像素坐标落在真实建筑上：图书馆 (815, 397)、主楼 (1000, 360)、新主楼 (1075, 815)、东门 (1265, 365)、田径场 (530, 810) 等；

- 底图版权归原图作者与学校所有，仅用于课程演示，不作商业用途。

## 9. 社区功能的边界

本期只做「轻社交」，不做真社区：

| 功能 | 实现 | 边界 |
|---|---|---|
| 收藏 | localStorage | 只在本机，不显示全站数字 |
| 声音记忆 | 预置 + 本机提交 | 提交后「待审核」，仅本机可见 |
| 票根 | DOM 卡片 + 复制链接 | 不生成图片、不建短链 |

这样做的原因：评论/点赞/上传需要账号、存储、审核、举报和内容安全，至少 4–6 人天，会直接挤掉时间轴。答辩时把「真社区」放在 v2 路线图，比做一个空评论区更稳。

## 11. 已知限制

1. **没有真实录音**：所有声音是合成音，音色与真实校园声景差距明显；这是本期最大的演示短板。
2. **地图是静态平面图**：建筑与编号来自官方平面图，但不能搜索、导航或看室内层。
3. **移动端音频**：iOS Safari 需要用户手势解锁，首次播放可能延迟；已用全局 pointerdown 解锁。
4. **收藏/投稿只在本机**：换设备或清缓存会丢失。
5. **无后端**：无法做真实评论、点赞、上传、审核队列。
6. **位图放大**：高倍缩放时底图会变糊，已限制 `maxZoom: 1.2`（`CRS.Simple` 相对缩放）。

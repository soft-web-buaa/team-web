01 / 组队

6 个人怎么分，才不互相等

6 人不是 6 条独立流水线。按“3 对搭档”组织，每对有一个接口人，减少跨人沟通成本。

R1产品 / 项目 / 答辩

定范围、砍需求、排进度、写演示脚本和答辩 PPT；所有“要不要加功能”的问题由他拍板。

R2前端 A：视觉与交互

页面结构、视觉风格、动效、核心交互；负责“用户第一眼看到的东西”。

R3前端 B：工程与集成

状态管理、接口联调、构建部署、代码合并；主分支的集成负责人。

R4后端 / 数据

API、存储、文件解析、抓取、WebSocket；负责“数据进得来、存得住”。

R5AI / 算法

模型调用、Prompt、评测集、识别/推荐/CRDT 策略；负责“效果说得清”。

R6测试 / 质量 / 文档

用例、兼容性、断网/多端/无障碍测试、录屏、README；负责“演示不翻车”。

Pair A：R2 + R3
所有用户能看到的界面与交互
Pair B：R4 + R5
数据、模型、接口、算法效果
Pair C：R1 + R6
范围、验收、演示、文档、兜底

03 / 方案详情

01 A11y Lens：给任意网页做“关怀模式”

产品形态是“浏览器扩展 + Web 主站”，不是普通网页。老师如果问“为什么不是一个网址”，答案在下面的技术边界里。

01
无障碍 · 浏览器扩展 + Web 主站

打开任意网页，一键切换成大字、去广告、可朗读的关怀版

用户安装扩展后，在任何已登录页面点一下，就能得到字号放大、干扰隐藏、正文重排、语音朗读和一份无障碍体检报告。

2 周只做这些（Must-have）

  • Manifest V3 扩展 + 注入式悬浮面板（不依赖 sidePanel，Chrome/Edge 都能跑）
  • 字号 100%–200%、行距、高对比、暗色模式
  • 隐藏干扰：广告、浮层、固定导航、cookie 横幅；支持“点选删除”
  • Readability 阅读模式：抽取正文，覆盖层重排
  • TTS 朗读 + 当前句高亮 + 自动滚动
  • axe-core 体检报告：问题列表、严重级别、修复建议
  • 恢复原样 + 设置持久化 + 分享配置链接

明确不做（Cut list）

  • 语音指令（国内 Chrome 的 SpeechRecognition 不稳定）
  • LLM 自动改写全文、自动生成复杂 alt 文本
  • 账号体系、云端同步、跨设备历史
  • 代理阅读器只作为 R4 的“有余力才做”项
  • 移动端适配（Chrome Android 基本不支持扩展）
DAY 2 检查点能在 3 个不同类型的页面上注入面板并放大字号
DAY 5 检查点阅读模式稳定，广告/浮层可隐藏，能一键恢复
DAY 7 检查点朗读 + 体检报告 + 设置持久化全部串通
演示脚本（90 秒） 打开本地 mock 的“小字 + 广告 + 低对比度”页面 → 一键关怀版 → 字号/对比度对比 → 点“朗读” → 打开体检报告 → 一键恢复原样 → 用一个真实公开页面收尾。
风险与降级

改崩页面 → 优先用覆盖层 + 一键恢复；TTS 没中文声音 → 用 Edge 本地语音 + 预生成音频兜底；扩展安装麻烦 → 准备书签小工具和录屏备用。

技术栈

Manifest V3、content script、Readability.js、axe-core、speechSynthesis、chrome.storage、Vite、可选 Playwright。

03
教育 · 多智能体 + 文档问答

DefenseRoom：AI 答辩陪审团

上传 PPT 或论文，三位性格不同的 AI 评委轮番追问；每个追问都能点回原文，最后生成一份“会被问倒的 10 个点”。

2 周只做这些（Must-have）

  • 上传 PDF/PPT → 抽取文本、页码、章节
  • 三种评委人设：技术追问 / 产品质疑 / 毒舌压力
  • 文字多轮追问，每轮 3 个问题，支持“继续追问”
  • 引用定位：点击引用跳到原文页/段并高亮
  • 结束报告：逻辑漏洞、证据不足、表达问题、预测分数
  • 10 个高风险问题清单 + 逐页修改建议

明确不做（Cut list）

  • 语音对话、实时打断、视频表情分析
  • 多人协作、账号体系、历史项目库
  • 实时评分动画、复杂数据看板
  • 非 PDF/PPT 格式（Word、图片先不支持）
DAY 3 检查点10 页 PDF 能稳定解析出带页码的 chunk
DAY 5 检查点多轮对话 + 引用能跑通，引用可点击定位
DAY 7 检查点报告生成 + 高风险问题 + 逐页建议闭环
演示脚本（90 秒） 上传一份 10 页课程 PPT → 选“技术评委” → 连续追问 3 轮 → 点开一个引用，原文高亮 → 生成报告 → 展示“最容易被问倒的 3 个点”。
风险与降级

解析乱 → 只支持 PDF + 纯文本 PPT；引用不准 → 按页/段存 chunk，强制模型返回 chunk id；幻觉 → 报告区分“原文事实”和“模型推断”。

技术栈

Next.js、pdf.js / pdfplumber、python-pptx、LLM API、SSE 流式输出、Tailwind、SQLite/Postgres。

04
协作基础设施 · 本地优先

LocalFirst Canvas：断网也能协作的白板

两个人打开同一个网页就能协作画图；拔掉网线继续画，网络恢复后自动合并，数据只存在各自浏览器里。

2 周只做这些（Must-have）

  • Yjs + y-websocket + y-indexeddb
  • 便签：新增、拖动、改文字、改颜色、删除
  • 在线光标 + 成员名字 + 在线状态
  • 撤销/重做（Yjs UndoManager）
  • 断网继续编辑，恢复后自动合并
  • 导出 JSON / PNG；房间号/分享链接

明确不做（Cut list）

  • 图片、自由绘制、复杂图形、评论
  • 账号体系、权限、版本历史、E2E 加密
  • 跨公网 P2P（WebRTC 的 NAT/信令会吃掉时间）
  • 移动端精细适配（能打开即可）
DAY 2 检查点两个窗口同步一个便签的增删改；不通过就换方案
DAY 5 检查点断网编辑 + 恢复合并跑通
DAY 7 检查点在线光标 + 撤销 + 导出 + 重连提示
演示脚本（90 秒） 两个窗口进同一房间 → 同时拖动便签 → 断网 → 各画各的 → 恢复网络 → 内容自动合并 → 展示在线光标 → 导出 PNG。
风险与降级

同步调不通 → Day 2 必须 go/no-go，失败就降级“单机白板 + 导入导出”；WebRTC 不稳 → 用 WebSocket；画布性能 → 便签用 DOM，不用 Canvas。

技术栈

React + Vite、Yjs、y-websocket、y-indexeddb、y-protocols/awareness、Node WS server、Konva 可选。

06
设计开发工具 · 多模态生成

Sketch2App：纸上画个页面，30 秒变成能点的网页

拍一张手绘线框图，自动识别按钮/输入框/卡片，生成可预览的页面；改改文案和颜色，就能导出 HTML。

2 周只做这些（Must-have）

  • 上传/拍照手绘线框，自动压缩图片
  • 视觉模型识别 5 类组件：按钮、输入框、卡片、导航、文本
  • 返回固定 JSON schema → React 渲染器预览
  • 文案、颜色、圆角的简单编辑
  • 导出 HTML（Tailwind）+ 分享预览链接
  • 识别置信度提示 + 手动纠正

明确不做（Cut list）

  • 拖拽式布局编辑器、自由画布
  • React/Next.js 代码导出（先只导 HTML）
  • 多页面、历史版本、账号、协作
  • 复杂动效、响应式断点、真实后端接口
DAY 3 检查点20 张草图 → JSON schema 稳定，5 类组件能识别
DAY 5 检查点JSON → 页面渲染，文案/颜色可改
DAY 7 检查点导出 HTML + 分享预览 + 置信度提示
演示脚本（90 秒） 现场在纸上画 3 个框 → 拍照上传 → 30 秒生成页面 → 手机扫码打开 → 改标题和按钮颜色 → 导出 HTML。
风险与降级

识别不准 → 限定 5 类组件 + 固定栅格 + 手动纠正；生成样式丑 → 只用一个设计系统模板；图片隐私 → 本地压缩 + 明确不长期存储。

技术栈

Next.js、多模态 LLM、JSON Schema、React 渲染器、Tailwind、iframe sandbox、HTML 导出。

04 / 2 周排期

把 10 天当成 3 个阶段

前 2 天只做技术验证，不写业务；第 8 天功能冻结；最后 2 天只做演示和兜底。

DAY 1
启动 + Spike

建仓库、CI、接口约定；每人认领角色；跑最难的技术点。

DAY 2
Go / No-Go

Spike 演示；范围冻结；API contract 定稿；不通过就换方案。

DAY 3–6
主链路

两对搭档并行开发；每天 15 分钟站会；Day 5 做第一次端到端。

DAY 7–8
集成 + 冻结

Day 7 全链路跑通；Day 8 功能冻结，只修 bug，不做新功能。

DAY 9–10
演示 + 兜底

彩排 3 次、录屏备份、准备离线 demo；Day 10 提交。

硬规则：Day 8 之后加功能，必须由 R1 同意，并且要砍掉一个同等工作量的功能。否则一律进“下版本”。

06 / 怎么拍板

用四个问题，十分钟选出项目

1. 组里有人能独立搞定浏览器扩展吗？

能 → 选 01，最稳；不能 → 01 也能做，但 R4 要提前准备代理阅读器或书签小工具作为备选形态。

2. 你们更想讲“AI 故事”还是“工程故事”？

AI 故事 → 03；工程故事 → 04；产品/设计故事 → 06。

3. 有人做过 React + 实时同步吗？

有 → 04 可以赌一把；没有 → 不要选 04，Day 2 的同步 spike 很可能过不了。

4. 你们想要“稳过”还是“现场炸场”？

稳过 → 01；炸场 → 06；两者都要 → 03（AI 追问 + 引用高亮，效果稳定）。

07 / 协作规则

6 人项目最容易死在“接口对不上”

每天必须发生的 3 件事

  • 15 分钟站会：昨天做了什么、今天做什么、被什么卡住。
  • 主分支可运行：任何人合并前，本地必须能跑通主流程。
  • 更新看板：每张卡只允许“待做 / 在做 / 待验收 / 完成”四态。

四条硬规则

  • Day 2 冻结 API contract：字段、错误码、示例 JSON 写进 README。
  • R3 是合并负责人：其他人只提 PR，不直接推 main。
  • 每个功能都有 fallback：演示前必须知道“如果它挂了，用什么替代”。
  • Day 8 功能冻结：之后只修 bug、只做演示优化。
